## 1.2. Диаграммы потоков данных 

### Запись пациента

Диаграмма: [dfd-reception.puml](dfd-reception.puml)

- **Входные данные:** ФИО, дата рождения, контактные данные
- **Обработка:** вручную в Excel на ресепшене
- **Выход:** запись в журнал, создание карточки пациента
- **Проблемы:** нет аудита, данные передаются в открытом виде

### Приём врача

Диаграмма: [dfd-doctor.puml](dfd-doctor.puml)

- **Входные данные:** данные пациента + результат осмотра
- **Обработка:** врач заполняет журнал Excel, передаёт на лабораторию
- **Выход:** направление на анализы
- **Проблемы:** файлы Excel не защищены, доступны всем

### Обработка анализов

Диаграмма: [dfd-lab.puml](dfd-lab.puml)

- **Входные данные:** направление, проба
- **Обработка:** анализ в лаборатории, отправка результата
- **Выход:** PDF-файл анализа
- **Проблемы:** пересылка PDF по почте, неаутентифицированные доступы

### Учёт платежей

Диаграмма: [dfd-payments.puml](dfd-payments.puml)

- **Входные данные:** ФИО пациента, сумма, услуга
- **Обработка:** Excel журнал, запись в 1С
- **Выход:** чек из ККМ
- **Проблемы:** нет валидации двойного учёта, возможны ошибки и дубли

## 2. Проблемные зоны безопасности данных

1. **Файлы Excel и сканы хранятся без контроля доступа**
    - Нет разграничения по ролям
    - Нет шифрования
    - Нет журналирования доступа

2. **1С в файловом режиме**
    - Отсутствует централизованная аутентификация
    - Не проводится аудит операций

3. **Отправка данных по почте**
    - Нет шифрования писем
    - Утечка возможна через компрометацию почтового ящика

4. **Все системы на одном сервере**
    - Компрометация одного компонента = доступ ко всем данным

5. **Нет политик RBAC/ABAC**
    - Любой сотрудник может получить доступ к любой информации

6. **Нет аудита доступа к медицинским данным**
    - Не отслеживается, кто и когда обращался к данным

7. **Нет поддержки конфиденциальности по умолчанию**
    - Принципы Privacy by Design не реализованы

## 3. Защита данных и предложения по тегированию

| Категория данных | Способ защиты | Возможный инструмент | Теги |
|------------------|----------------|------------------------|------|
| ФИО, контактные | Шифрование при передаче | HTTPS, TLS | `pii.basic` |
| Паспортные и адресные | Хранение в зашифрованной БД | PostgreSQL + TDE | `pii.sensitive` |
| Медицинская информация | Обезличивание, RBAC | Keycloak + Spring Security | `phi.medical` |
| Финансовая информация | Аудит, логирование, DLP | Wazuh, Elastic | `pii.financial` |
| Вложения | Шифрование на уровне файлов | VeraCrypt, GnuPG | `confidential.file` |

## 3.1. Рекомендации по улучшению

### Меры безопасности:
- Внедрить централизованное хранилище с RBAC и аудитом
- Настроить VPN-доступ с двухфакторной авторизацией
- Внедрить протоколы шифрования при передаче данных (HTTPS, SMTPS)
- Перевести 1С на клиент-серверный режим с резервным копированием
- Настроить DLP и систему оповещений о попытках утечки

### Управление доступом:
- Роли: врач, ресепшен, бухгалтер, склад, IT
- Тегирование данных и связка с политиками доступа
- Внедрение атрибутов (ABAC) по локации, устройству и роли

### Инструменты:
- Keycloak (SSO, RBAC)
- PostgreSQL + Transparent Data Encryption
- Spring Security + Attribute-based policies
- Elasticsearch + Audit trails
- MinIO/S3 как надёжное файловое хранилище
